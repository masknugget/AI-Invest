# AI-Invest 下一阶段产品规划（产品视角版）

> 版本：v2.0 ｜ 日期：2026-11-24
> 定位说明：本文跳出代码实现，从"一个股票投资产品应该长什么样"出发做规划。技术可行性评估仍参考现有代码能力，但功能选型以用户价值为唯一标准。

---

## 1. 现状盘点（先对齐，再规划）

### 1.1 当前产品的本质：一台"重型分析引擎"

抛开接口清单，用户今天能做的事只有一条主线：

> **找到一只股票 → 发起 AI 深度分析（等几分钟）→ 读报告**

加上组合诊断、每日推荐、AI 对话，本质上都是这条主线的变体。这是一个**"分析请求-响应"式的工具**，而不是一个**"投资陪伴"式的产品**。

### 1.2 从产品版图看，缺什么

对照一个完整股票投资产品的标准能力版图：

| 能力层 | 标准产品应有的 | 当前状态 |
|--------|----------------|----------|
| **看盘层** | 大盘地图、板块热力、涨跌分布、资金流、市场情绪 | ❌ 完全没有 |
| **盯盘层** | 自选股、价格预警、异动提醒 | ❌ 完全没有（前端有壳，后端为空） |
| **个股研究层** | 个股全景页（行情+财务+新闻+公告）、杜邦分析、同行对比 | ⚠️ 只有 AI 分析报告，无结构化财务研究工具 |
| **决策辅助层** | AI 分析、荐股、组合诊断、压力测试 | ✅ 这是当前唯一做厚的层 |
| **学习层** | 股票知识库、投资课程、术语百科 | ❌ 前端有 Learning 页面，无内容体系 |
| **实践层** | 模拟交易、策略回测 | ❌ 前端有壳无后端 |
| **交易层** | 实盘交易 | ❌（且应明确不做，见路线图） |

**核心诊断：产品头重脚轻。** 决策辅助层（AI 分析）做得很深，但它是低频行为——用户不会每天发起深度分析；而看盘、盯盘、学习这些**每日高频场景全部缺失**。没有高频场景，低频的 AI 分析就没有流量来源，用户也没有每天打开产品的理由。

### 1.3 代码侧的两个事实（仅作约束，不展开）

- 前端有 PaperTrading / Screening / Favorites / Scheduler 等页面，但后端无对应接口——说明产品意图早已存在，工程落地断档；
- 通知系统（REST + WebSocket）已就绪——这是预警、提醒类功能的重要现成地基。

## 2. 用户与场景假设

### 2.1 目标用户

**主用户：个人进阶投资者**（有 1-5 年经验、有自己的选股逻辑、愿意花时间研究的散户）。
**次用户：投资新手**（想学但无从下手）。
推断依据：产品提供 A股/港股/美股多市场 + 多维度 AI 分析，形态是自助式 Web 工具而非机构终端。

### 2.2 用"投资者的一天"重构场景

| 时段 | 场景 | 用户需求 | 当前覆盖 |
|------|------|----------|----------|
| **盘前** | S1 感知市场：今天市场整体什么状态？哪些板块在动？有什么重大新闻？ | 快速建立市场认知，确定今日关注方向 | ❌ 未覆盖 |
| **盘中** | S2 盯盘：我的自选股涨了跌了？有没有触发我关心的价位或事件？ | 被动接收提醒，不主动刷屏 | ❌ 未覆盖 |
| **盘中/盘后** | S3 快速研究：看到一只异动股，30 秒内判断"这是什么公司、值不值得深入" | 个股全景一页看懂 | ⚠️ 只有慢速深度分析，无快速概览 |
| **盘后** | S4 深度研究：对重点标的做基本面、财务、估值的系统分析 | AI 分析 + 财务拆解工具 | ✅ 部分覆盖（缺结构化财务工具） |
| **盘后/周末** | S5 组合复盘：我的持仓整体健康吗？要怎么调？ | 组合诊断 + 调仓建议 | ✅ 已覆盖 |
| **闲暇** | S6 学习成长：补投资知识、理解分析方法、模拟练手 | 知识库 + 模拟盘 | ❌ 未覆盖 |

**关键洞察：S1/S2/S6 三个高频场景全部空白，产品当前只服务"已经决定研究某只股票"之后的那 10% 时间。**

## 3. 候选功能清单（7 项）

### F1. 大盘地图（市场热力图 + 板块监测）

- **功能描述**：开盘即见的"市场全貌首页"——行业板块热力图、涨跌家数、成交额分布、热门概念，让用户 10 秒感知今天市场状态。
- **目标场景**：S1（盘前感知）。
- **产品价值**：R=全体用户的**每日打开理由**，I=极高（这是股票产品的流量入口，同花顺/雪球的日活都建立在行情地图上），C=高。RICE 全清单最高。
  金融属性：**准实时数据要求**——盘中热力图需要分钟级行情刷新，这是本项目首次对实时性提要求；数据延迟必须在 UI 显著标注（"延迟 15 分钟"类披露是行业惯例，也是免责手段）。
- **技术可行性**：需要新增行情聚合接口 + 前端热力图组件（ECharts 已在技术栈内）；数据源复用现有 AKShare/Tushare 通道，但**需评估这些数据源的盘中刷新能力与配额**【待确认：现有数据管道是否支持分钟级拉取】。
- **工作量**：M。依赖与风险：数据源盘中限流风险；若只能做到日频更新，产品价值打七折（变成"盘后复盘地图"）。

### F2. 价格与事件预警中心

- **功能描述**：用户对自选股设置预警（到价、涨跌幅、成交量异动、重大新闻），触发后通过站内通知/WebSocket 实时推送。
- **目标场景**：S2（盘中盯盘）。
- **产品价值**：R=活跃用户，I=极高（预警是**召回之王**——一条"你关注的XX涨停了"的推送能把流失用户拉回产品），C=高。
  金融属性：**准确性与及时性双重要求**——误报/漏报会直接损害用户信任（"预警没响害我错过卖点"是致命口碑事件）；预警涉及"触发时刻的行情快照"，需留存记录以备争议。
- **技术可行性**：通知地基（WebSocket + notifications）已就绪，需新增预警规则引擎 + 行情轮询调度（复用现有 Redis 队列 + APScheduler 体系）。
- **工作量**：M。依赖与风险：实时性依赖数据源刷新频率（与 F1 同一约束）；预警风暴防护（大盘剧烈波动时单用户可能触发数十条，需做合并降噪）。

### F3. 自选股闭环

- **功能描述**：收藏股票、分组打标签，自选股列表即"个人盯盘台"，一键发起分析、设置预警、查看相关新闻。
- **目标场景**：S2/S3 的承载容器，同时是 F1/F2 的落点。
- **产品价值**：R=全体用户，I=高（自选股是投资产品的**留存基础设施**，没有它用户每次从零开始），C=高。
  金融属性：行情快照展示，实时性要求中等；不涉及资金。
- **技术可行性**：前端页面与接口契约已存在，补后端 CRUD + 行情快照聚合即可。
- **工作量**：M（其中大半是前端联调收尾）。依赖与风险：无重大风险，是确定性最高的功能。

### F4. 个股全景页（一页看懂一只股票）

- **功能描述**：每只股票的结构化落地页——实时行情、关键指标（PE/PB/市值/换手）、主营构成、最新公告新闻、AI 分析入口、相似公司。30 秒建立初步认知。
- **目标场景**：S3（快速研究）。
- **产品价值**：R=全体用户，I=高（它是大盘地图、预警、搜索结果、推荐列表的**共同落地页**——所有流量最终都需要一个"这只股票是什么"的页面承接），C=高。
  金融属性：多源数据聚合页面，**数据口径一致性**是主要风险（不同来源的财务指标可能打架，需统一口径并标注来源）。
- **技术可行性**：数据字段大部分可从现有 MongoDB 集合（`stock_basic_info`、`stock_daily_quotes`）+ dataflows 层聚合，需新增个股聚合接口；前端 ECharts 能力现成。
- **工作量**：M。依赖与风险：这是**平台型能力**——做完它，F1/F2/F3 的流量才有承接处，应尽早做。

### F5. 财务分析模块（杜邦分析 + 三表可视化 + 同行对比）

- **功能描述**：把 ROE 拆解为杜邦三因子（净利率×周转率×杠杆），三表关键科目趋势可视化，与同行业公司横向对比，让基本面分析从"AI 一段话"变成"可交互的数据工具"。
- **目标场景**：S4（深度研究）。
- **产品价值**：R=进阶用户（约 30-40%），I=中高（深化研究能力，与 AI 分析形成"数据+观点"互补），C=中高。
  金融属性：**准确性要求最高的一项**——财务数据错一个小数点就是误导决策；财报数据有披露滞后性，必须标注报告期；A股/港股/美股财报科目体系不同，需分市场适配。
- **技术可行性**：需要财务数据源（Tushare 有财务接口，但**覆盖度和及时性待确认**）；杜邦计算逻辑简单，主要工作在数据清洗与分市场科目映射。
- **工作量**：M-L。依赖与风险：财务数据源质量是最大不确定性【待确认：Tushare 积分享有的财务数据权限等级】；三市场科目映射是一次性重活。

### F6. 股票知识库（学习中心内容化）

- **功能描述**：体系化的投资知识内容——术语百科（什么是 PE/ROE/护城河）、分析方法教程（如何读财报、如何做估值）、AI 分析方法论说明（我们的智能体在做什么），并与 AI 对话打通（看不懂直接问）。
- **目标场景**：S6（学习成长），服务新手用户。
- **产品价值**：R=新手用户，I=中（学习是**拉新与留存的长尾资产**，内容可被搜索引擎收录带来自然流量），C=中（内容运营是持续投入，非一次性开发）。
  金融属性：**内容合规敏感**——教程案例不得构成具体标的推荐（"举例：茅台"也有荐股嫌疑，需用历史/虚构案例）；AI 生成内容需人工审核后发布。
- **技术可行性**：前端 Learning 页面已有骨架，需要内容管理后端（可复用现有配置中心的 CRUD 模式）+ 内容生产流程。
- **工作量**：工程 S-M，**内容生产是长期 L**。依赖与风险：最大的成本不在代码而在内容运营人力【待确认：是否有内容运营资源】。

### F7. 合规护栏与免责声明体系（贯穿性，非可选）

- **功能描述**：所有建议类输出（AI 分析、推荐、调仓方案、知识库案例）统一注入免责声明、数据时间戳与来源标注；用户首次使用确认风险揭示书；分析结论全量留痕可追溯。
- **目标场景**：所有场景的底层前提。
- **产品价值**：不产生直接用户价值，但**决定产品能否公开运营**。产品当前已有荐股、调仓建议功能在线运行，无证券投资咨询资质下的合规敞口是"现在进行时"。
- **技术可行性**：统一响应包装 + 前端组件 + 确认记录落库。工作量 S-M。
- **依赖与风险**：免责声明只是缓解措施，不能替代资质；需法务参与定性【待确认：运营主体与法务资源】。

## 4. 优先级排序与路线图

### 4.1 排序逻辑

排序原则：**先补"每天打开产品的理由"（高频场景），再深化研究工具（低频增强），合规贯穿始终。**

| 优先级 | 功能 | 理由 |
|--------|------|------|
| **P0** | F3 自选股闭环 | 一切高频场景的容器：没有自选股，预警没有对象，大盘地图没有个性化，流量没有沉淀 |
| **P0** | F7 合规护栏 | 现有荐股/调仓功能的合规敞口已在发生，先于任何新功能 |
| **P1** | F2 预警中心 | 召回抓手，通知地基现成；与 F3 组合成最小盯盘闭环 |
| **P1** | F4 个股全景页 | 平台型能力：所有入口（搜索/推荐/地图/预警）的共同落地页 |
| **P1** | F1 大盘地图 | 日活入口，但依赖准实时数据能力【待确认】，若数据源不支持分钟级则降级为盘后复盘版 |
| **P2** | F5 财务分析/杜邦 | 深度增强，服务进阶用户；数据源质量确认后启动 |
| **P2** | F6 知识库 | 长尾拉新资产，依赖内容运营资源到位 |

### 4.2 分阶段路线图

**近期（迭代 1–2，约 4-6 周）：建立最小盯盘闭环**
- F7 合规护栏（先行，法务参与）
- F3 自选股闭环（含前端已存在页面的后端补全）
- F2 预警中心（自选股 + 预警 = 用户第一次有理由每天回来）
- 并行：评估行情数据源的盘中刷新能力（决定 F1 形态）

**中期（迭代 3–5，约 2-3 个月）：建立流量入口与承接**
- F4 个股全景页（所有流量的落地页）
- F1 大盘地图（根据数据源评估结果定实时/盘后版本）
- 模拟交易（承接此前规划，作为学习实践的闭环，L 级工作）

**远期（迭代 6+）：深度与资产**
- F5 财务分析/杜邦模块
- F6 知识库内容化（需内容运营先行）
- 市场情绪仪表盘（恐贪指数、北向资金、龙虎榜——可作为大盘地图的子模块顺势推出，不单独立项）

**明确不做：**
1. **实盘交易对接** —— 无经纪牌照，资金安全责任不可承受；
2. **UGC 社区/跟单** —— 非法荐股与内容审核风险极高，偏离 AI 分析主线；
3. **Level-2 高频行情** —— 授权成本与用户群不匹配；
4. **期权/期货/加密货币** —— 适当性管理复杂度与风险超出当前阶段。

## 5. 关键决策点

### D1. 运营主体与合规定性【最高优先级，阻塞项】
- **问题**：产品以什么定性运营？是否有证券投资咨询资质？
- **推荐**：获资质前定性为"AI 投研教育工具"：建议类输出统一降级为"研究参考"措辞 + 显著免责 + 禁指令式表述；推荐功能更名"AI 研究关注名单"。
- **需补充**：运营主体、上线范围（公网/内部）、法务资源。

### D2. 实时行情策略：新功能带来的新问题
- **问题**：大盘地图和预警都要求准实时行情，现有免费数据源（AKShare/Tushare）的盘中能力和配额能否支撑？要不要采购实时行情源？
- **推荐**：分两档决策——若免费源能支撑分钟级刷新，先上线；若不能，F1 降级为"盘后复盘地图"先上线，预警降级为"收盘后批量触发"，同时评估采购行情源的成本。**不建议在产品验证期采购昂贵的实时行情授权。**
- **需补充**：各数据源盘中刷新频率与限流实测数据。

### D3. 触达通道：预警发到哪里？
- **问题**：预警的价值依赖触达，但产品是 Web 端——用户不开网页就收不到。要不要做小程序/App/邮件/微信服务号推送？
- **推荐**：先做**站内 + 邮件**（成本最低），同步评估**微信服务号模板消息**（国内个人投资者触达率最高的通道，且无需下载 App）。App 在 DAU 验证前不做。
- **需补充**：目标用户的触达偏好；微信服务号主体资质。

### D4. 用户分层取舍：新手还是进阶？
- **问题**：知识库服务新手，杜邦分析服务进阶，资源有限先服务谁？
- **推荐**：**先进阶后新手**。理由：进阶用户与现有 AI 分析能力匹配度最高、付费意愿最强；新手市场需要内容运营长期投入，且获客成本高。知识库放 P2 等待内容资源到位。
- **需补充**：现有用户的构成数据（若有）。

### D5. 数据准确性责任边界
- **问题**：财务数据、行情数据出错导致用户损失，产品责任边界在哪？
- **推荐**：UI 全链路标注"数据来源 + 更新时间 + 仅供参考"；关键页面（财务、行情）增加数据校验异常提示机制（如数据缺失/异常波动时显著提示）。这是 F7 合规护栏的一部分，随 P0 落地。
- **需补充**：无法务意见前，措辞需保守。
